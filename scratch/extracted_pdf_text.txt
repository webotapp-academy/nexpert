SECTION  01
The Honest Reality Check
Read this before writing a single line of code.
What your developer actually built (MVP1)
A session booking marketplace identical to Topmate and Calendly. Coaches list profiles, learners book sessions, star
ratings display. The codebase is well-built PHP — auth, KYC, Razorpay payments, Zoom, admin panel. But there is
zero trust infrastructure. No behavioral signals. No Trust Score. No ECI. The entire MVP2 differentiation does not exist
yet in any file.
What MVP2 actually is (one sentence)
Every session completed on the platform automatically writes behavioral events to a database table. A deterministic
formula reads those events and produces a Trust Score (0-100) for each expert. That score replaces star ratings
everywhere a learner sees an expert.

SECTION  02
The 6 AI Agents — Fully Explained
What each agent actually is, what it does, and what code implements it.
IMPORTANT: Most of these are not "AI" — they are deterministic functions
The word "agent" in this context means "a piece of code responsible for one specific job that runs automatically when
triggered." Only 1 of the 6 uses actual AI (NLP sentiment analysis). The rest are PHP/Python functions reading from
and writing to the database. Do not let any developer charge you for building "AI agents" — these are simple database
operations with a formula.
1
Signal Collector Agent
Event Listener
WHAT IT DOES
Listens for specific events on the platform (session completed, booking made, feedback submitted, no-show) and writes a
record to the eci_signals table. It is a function called at the end of existing API endpoints.
WHY IT EXISTS
Without this nothing else can run. Real signals are the only thing that makes Trust Score data meaningful. Every other agent
depends on this table having data.
TRIGGER
Triggered by: (a) Zoom webhook when session ends, (b) feedback form submit, (c) booking status change to
completed/cancelled/no_show, (d) repeat booking detection.
OUTPUT
One row in eci_signals: {expert_id, signal_type, signal_value, recorded_at}
 2
Behavior Analysis Agent
Aggregator
WHAT IT DOES
Reads all signals from eci_signals for a given expert and groups them by type. Counts occurrences of each signal type and
sums their values. Produces a dictionary of aggregated signal data ready for the scoring formula.
WHY IT EXISTS
The raw signals are individual events. You need aggregated counts to compute percentages and ratios. This step separates
data collection from data computation.
TRIGGER
Called by the Trust Scoring Agent (Agent 6) every time a new signal arrives. No external trigger — internal function call only.
OUTPUT
Python dict or PHP array: {session_completed: 12, feedback_positive: 8, session_cancelled: 1, ...}

--- Page 4 ---
3
Consistency Agent
Time-Series Analyzer
WHAT IT DOES
Looks at the distribution of signals over time — not just totals. Checks if the expert has been consistently active (sessions
spread over months) vs bursty (all sessions in one week). Produces a consistency ratio used in the c_consistency
component.
WHY IT EXISTS
An expert with 10 sessions last week and nothing for 6 months should not score the same as an expert with 2 sessions per
month for 5 months. Consistency over time is what makes trust meaningful.
TRIGGER
Called as part of the scoring computation. Also runs a scheduled job (daily cron) to decay scores of experts who have been
inactive for 60+ days.
OUTPUT
c_consistency score (0.0 to 1.0) and an optional decay_flag if inactive for 60+ days.
4
Outcome Agent
Result Verifier
WHAT IT DOES
Reads outcome_verified signals — signals written when a learner marks a goal as achieved in their dashboard.
Cross-checks that the verified outcome corresponds to a real completed booking. Calculates the outcome verification rate
(verified outcomes / total sessions).
WHY IT EXISTS
Anyone can claim outcomes. This agent only counts outcomes that have a matching completed booking and explicit learner
confirmation. This is the hardest signal to fake and the most valuable one.
TRIGGER
Runs when a learner marks a goal as achieved (POST to outcome API). Also re-checks on demand if admin suspects fraud.
OUTPUT
Updated c_prediction_accuracy component. Also sets outcome_verification_rate on the expert record.

--- Page 5 ---
5
Verification Agent
Identity Checker
WHAT IT DOES
Reads the KYC verification table (already built — expert_kyc). When an admin approves KYC, this agent sets
is_eci_verified=1 on the experts table. Verified experts get a teal checkmark badge visible to learners and receive a small
score boost (+2 to accountability component).
WHY IT EXISTS
Trust Score without identity verification is gameable. Any behavioral signal is more credible if we know the expert is a real
person whose identity has been confirmed.
TRIGGER
Triggered when admin changes KYC status to approved in the KYC verification panel (admin already built — just add a
hook).
OUTPUT
Sets is_eci_verified=1 on experts table. Triggers one computeECI() recompute to update score with verified bonus.
 6
Trust Scoring Agent
Formula Engine
WHAT IT DOES
The orchestrator. Called after any new signal arrives. Calls Behavior Analysis Agent, gets the 5 component scores, applies
the ECI weights (30/25/20/15/10), produces the final score, assigns a band
(Sovereign/Established/Verified/Emerging/Unverified), and saves the result to both experts.eci_score and eci_scores history
table.
WHY IT EXISTS
This is the only agent that writes to the experts table. All other agents feed data into this one. Separating the compute step
means you can change the weights formula in one place without touching signal collection.
TRIGGER
Called by: Signal Collector (after every new signal), admin recompute button, daily cron (for decay updates).
OUTPUT
Updated experts.eci_score, experts.eci_band, experts.eci_band_color, experts.eci_last_computed. New row in eci_scores
history.
The honest technical summary of all 6 agents
Agent 1 = 4-line function appended to 6 existing API files. Agent 2 = 15-line PHP array aggregation. Agent 3 = 10-line
formula using COUNT() SQL queries. Agent 4 = 8-line outcome cross-check function. Agent 5 = 3-line hook in admin
KYC approval handler. Agent 6 = the 60-line computeECI() function in eci_engine.php. Total new code: approximately
100 lines. Any developer who quotes more than 3 days for all 6 agents is overcharging.

SECTION  04
The No-Agent Version
Build MVP2 without any AI framework. Just PHP + SQL + math. Faster to ship, easier to maintain.
The simplest possible MVP2: 3 database tables + 6 function calls + 1 UI change
You do not need LangChain, LangGraph, CrewAI, AutoGen, or any AI framework. The entire Trust Score system is a
deterministic formula reading from a database. Here is the minimum viable implementation of every agent as plain
PHP functions.
THE MINIMUM IMPLEMENTATION — ALL 6 AGENTS AS 1 PHP FILE
includes/eci_engine.php — All 6 Agents in 1 File (~60 lines total)
// ■■■ AGENT 1: Signal Collector ■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■
function recordSignal($expert_id, $signal_type, $value, $pdo) {
    $pdo->prepare("INSERT INTO eci_signals (expert_id,signal_type,signal_value)
        VALUES(?,?,?)")->execute([$expert_id,$signal_type,$value]);
    return computeECI($expert_id, $pdo); // calls Agent 6 immediately
}
// ■■■ AGENTS 2+3+4+5 are all inside computeECI() ■■■■■■■■■■■■■■■■■
// ■■■ AGENT 6: Trust Scoring Agent (calls all others internally) ■
function computeECI($expert_id, $pdo) {
    // Agent 2: Aggregate signals
    $rows = $pdo->prepare("SELECT signal_type, signal_value FROM eci_signals
                WHERE expert_id=? ORDER BY recorded_at DESC");
    $rows->execute([$expert_id]); $signals = $rows->fetchAll();
    $total=count($signals); $counts=[]; $sums=[];
    foreach($signals as $s) { $counts[$s["signal_type"]]++;
        $sums[$s["signal_type"]]+=(float)$s["signal_value"]; }
    // Agent 3: Consistency
    $c_cons = max(0, min(1, 1-($counts["session_cancelled"]??0)*2/$total));
    // Agent 4: Outcomes
    $pos = ($sums["outcome_verified"]??0)+($sums["feedback_positive"]??0);
    $neg = ($counts["session_no_show"]??0)*1.5+($counts["feedback_negative"]??0);
    $c_pred = max(0, min(1, ($pos-$neg)/$total));
    // Agent 5: Verification bonus
    $c_depth = min(1, ($counts["session_completed"]??0)/50);
    $c_acct = max(0, min(1, 1-($counts["session_no_show"]??0)*2/$total));
    $m=$pdo->prepare("SELECT months_active FROM experts WHERE id=?");
    $m->execute([$expert_id]); $mo=(int)$m->fetchColumn();
    $c_long = $mo>0 ? log1p($mo)/log1p(120) : 0;
    // Final score: 30/25/20/15/10 weights
    $score=round(($c_pred*.30+$c_cons*.25+$c_depth*.20+$c_acct*.15+$c_long*.10)*100,1);
    // Assign band, save to DB, log history, return result
    // ... (band assignment + 2 SQL writes — full code in eci_engine.php)
}

What is Claude Code?
Claude Code is a command-line tool (terminal app) made by Anthropic that has access to your entire codebase. You
type instructions in plain English, it reads your files, writes code, runs tests, and makes changes. It is not a chat
interface — it is an autonomous coding agent that works inside your actual project folder.

SECTION  08
Hiring an IIT / AI Engineer
What to test, what to pay, what to never outsource.
What you actually need vs what you will be sold
Most candidates will come with impressive CV lines — LLMs, RAG, vector databases, fine-tuning. None of that is
relevant to MVP2. What you need is someone who can write clean PHP or Python, understands SQL, and can
implement a deterministic algorithm in a legacy codebase without breaking anything. The IIT brand matters less than
the ability to read existing code and extend it precisely.
THE TEST ASSIGNMENT — GIVE THIS BEFORE ANY INTERVIEW
2-hour take-home test (no payment required, share as PDF)
Give them this task: "Here is a PHP file (session-config.php) and a database schema (experts table). The experts table
has columns eci_score FLOAT DEFAULT 50.0, eci_band VARCHAR(20), eci_band_color VARCHAR(10). Write a
PHP function called computeECI(int $expert_id, PDO $pdo): array. It should (1) query a table called eci_signals for all
rows with this expert_id, (2) count session_completed and feedback_positive rows as positive signals, count
session_no_show as negative, (3) compute a score as (positive - negative*1.5) / total * 100, clamped to 0-100, (4)
assign a band: above 75 = Established, above 50 = Verified, else Unverified, (5) update the experts table with the
score and band, (6) return an array with score, band, and band_color." What you are testing: can they read existing
code structure, write clean PDO, handle edge cases (zero signals), and return the right data type. If they pass with
